# Архитектура и иерархия Logos

## Назначение

Logos — **отдельный публичный сайт на собственном домене**. JSInteractive обеспечивает управление материалами через общую админку и выдачу опубликованных данных через публичный GET API. Пользовательские страницы Logos не должны содержать административную авторизацию, редактор, секреты или прямой доступ к базе JSInteractive.

## Иерархия содержимого

```text
Logos
├── Главная (/)
│   ├── Представление проекта
│   ├── Рубрики (публичный API)
│   ├── Новые материалы (публичный API)
│   └── Подход к исследованию
└── Каталог знаний (/catalog)
    └── Рубрика (/catalog/:catName)
        └── Публикация (/catalog/:catName/:slug)
            ├── Аннотация и сведения о публикации
            ├── Текст: заголовки второго и третьего уровня
            ├── Ключевые слова
            └── Источники и литература
```

**Важно:** текущий API возвращает плоский список рубрик; вложенные подрубрики и граф связей между материалами не следует имитировать на фронтенде. Это отдельная задача по модели данных JSInteractive и публичному API. «Исследование» и «статья» могут развиваться как профили публикаций без создания параллельной CMS.

## Правила зависимостей

1. Страницы обращаются к `PublicContentService`, управляют состоянием загрузки, вызывают SEO-обновление и собирают компоненты.
2. Компоненты получают данные через `props` и не обращаются напрямую к админке, БД или другим приватным сервисам.
3. `domain/publication.mjs` содержит чистые функции: профиль, поиск по загруженным элементам, дату, склонения, время чтения. Эту логику использует и SEO.
4. Компонент `ArticleContent` отвечает только за отображение **уже безопасного HTML** и построение оглавления по `h2/h3`. Санитизация HTML — обязанность источника публикаций, JSInteractive. Не передавать недоверенный HTML напрямую.
5. `styles/tokens.css` — единый источник визуальных токенов. Не копировать значения цветов по страницам без причины.
6. Маршруты `/lecture/...` сохранены как клиентские редиректы. Для SEO-миграции опубликованного сайта отдельно понадобятся серверные HTTP 301.

## Поток данных

```text
Админка JSInteractive → Хранилище JSInteractive → публичный GET API
                                                ↓
                              API/PublicContentService.js
                                                ↓
                                  pages/ + domain/
                                                ↓
                                  components/ + seo/
                                                ↓
                                     сайт Logos
```

## Проверки

- `npm run lint` — ESLint для Vue, JavaScript и тестов.
- `npm run format:check` — детерминированная проверка Prettier.
- `npm run verify` — проверки границ клиента, связности импортов, структуры компонентов, доменной логики, SEO и оглавления.
- `npm run build` — production-сборка Vue.
- Ручная приёмка: переходы со старых URL, мобильная навигация, пустые рубрики, длинные статьи, оглавление, библиография и прямое открытие внутренних URL на веб-сервере.

**Не реализовано в текущем рефакторинге:** иерархические подрубрики на стороне API, полнотекстовый серверный поиск, SSR/пререндеринг для SEO и новые типы редактора. Эти функции требуют отдельных решений на уровне контракта JSInteractive.
